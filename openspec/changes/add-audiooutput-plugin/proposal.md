## Why

The `PlayerInfo` plugin exposes two separate APIs — `AtmosMetadata` (atmos capability) and `SoundMode` (current audio output mode) — that clients must individually query and combine to determine whether Dolby Atmos Experience is active. This split forces every consumer to duplicate the combination logic and subscribe to two separate change events. A dedicated `AudioOutput` plugin resolves this by owning all audio output capabilities in one place, exposing a single `dolbyAtmosExperience` boolean and notifying subscribers only when the combined result actually changes.

## What Changes

- **New plugin**: `org.rdk.AudioOutput` Thunder plugin introduced in the `entservices-audiooutput` repository.
- **New C++ interface**: `Exchange::IAudioOutput` added to ThunderInterfaces (`interfaces/IAudioOutput.h`), with autogenerated JSON-RPC stubs (`JAudioOutput.h`, `JsonData_AudioOutput.h`).
- **New JSON-RPC method**: `org.rdk.AudioOutput.dolbyAtmosExperience` — returns `true` when Dolby Atmos Experience is fully enabled, `false` otherwise.
- **New JSON-RPC notification**: `org.rdk.AudioOutput.onDolbyAtmosExperienceChanged` — fires to all subscribers when the computed state changes.
- **Internal implementation**: `AudioOutputImplementation` copies the `AtmosMetadata` and `SoundMode` logic from `entservices-playerinfo/plugin/DeviceSettings/PlatformImplementation.cpp` directly into this plugin. These are private implementation methods; they are **not** exposed individually via the `IAudioOutput` interface.
- **Event subscriptions**: The implementation subscribes to `AtmosCapabilityChanged` (from `DisplaySettings`) and `audioModeChanged` (from `PlayerInfo`) via COM-RPC to maintain an internal cache and trigger notifications.
- `PlayerInfo.AtmosMetadata` and `PlayerInfo.soundMode` are **not removed** — they continue to exist in their current plugin.

## Capabilities

### New Capabilities

- `audiooutput-plugin`: The complete `AudioOutput` Thunder plugin — plugin shell, out-of-process implementation, build system, configuration, and the `dolbyAtmosExperience` API with its change notification.

### Modified Capabilities

_None — no existing capability requirements are changing._

## Impact

- **New repository**: `entservices-audiooutput` (this repo) receives the full plugin source tree under `plugin/`.
- **ThunderInterfaces** (external): Requires a new `IAudioOutput` interface header and ID allocation in `Ids.h`.
- **Dependencies**: `dshal` / DeviceSettings library (same as PlayerInfo), `${NAMESPACE}Plugins`, `${NAMESPACE}Definitions`, `CompileSettingsDebug`.
- **CI/CD**: `L1-tests.yml`, `L2-tests.yml`, `L2-tests-oop.yml`, and `cov_build.sh` must be updated to include `PLUGIN_AUDIOOUTPUT=ON`.
- **No breaking changes** to existing `PlayerInfo` APIs.
